# PresenceKit 0.1.0-beta.2

An importable Swift 6 / macOS 13+ sensing library and opt-in unattended player integration, for Intel and Apple silicon. No third-party package dependencies, identity recognition, recording, uploads or cloud processing.

- `PresenceKit` retains its low-level run-until-failure monitor, ordered callbacks, separate lighting events, capture caps and exclusive source-session ownership.
- `PresenceAutomation` adds classified transient recovery, bounded exponential delays, injectable timing/jitter, health-based reset, observable recovery/mode changes and explicit recognition fallback. Permission denial, unsupported settings/caps, startup timeout, duplicate ownership, slow consumers and unclassified errors are terminal; a new lifecycle run is an explicit manual retry.
- `PresencePlayback` exposes an injectable `PresencePlaybackController` and combined-reason `PresenceLifecycle`, plus the native `PresencePlayerController`. Output is idempotent, motion suppression precedes illumination changes, local-input grace owns one cancellable deadline/recheck, and stale absence work cannot authorize a later display-sleep request.
- The reference agent uses this shared controller, displays raw sensing separately from effective activity and degradation, retains the player/playhead on monitoring restart, offers explicit media reload and one-shot diagnostics, and drains owned work on quit or session/system suspension.
- Defaults remain motion-only sensing, 120-second absence, and safe pause/hide on unknown. Display management and keeping the system awake are independent opt-ins. Media plays once by default; `--loop` is explicit. Requested recognition uses either motion fallback with 120 seconds of additional absence grace or `--fallback pause`; strict fallback requires enabled recognition. Default local-input grace is 60 seconds.
- Native Intel/Apple-silicon debug/release, packaging/signature/plist checks, no-camera smoke/argument checks, macOS-13-targeted example typecheck, real external package consumer and both Linux compiler lanes gate publication. See the publication run and retained source/toolchain/test artifacts for actual evidence; physical camera, display and energy acceptance remain separate in issue #1.

Compatibility: the low-level monitor does not start retrying silently. Exhaustive switches must account for typed `captureFailure`, recognition `warmingUp`, and the new host recovery/mode events. Unclassified `cameraUnavailable(String)` is now terminal rather than inferred retryable from its message. Import `PresencePlayback` for host playback/lifecycle APIs; `PresenceKit` itself never plays media or changes power settings.

Pin the published tag exactly: `.package(url: "https://github.com/jmonster/PresenceKit.git", exact: "0.1.0-beta.2")`. This document is a release-note template until the gated tag exists. Published version tags are never moved; later successful main builds with an already-published version skip publication rather than retargeting it.

This is a source prerelease, not a notarized application or a 1.0 API-stability commitment. Motion fallback does not establish reliable stationary-person detection. Processing duty is not a wattage bound or a latency/energy guarantee. A sleeping computer cannot analyze camera frames, display sleep is not system sleep, and explicit user sleep is not prevented. Building for macOS 13 is not execution proof on every older OS, compiler or OCLP machine.
